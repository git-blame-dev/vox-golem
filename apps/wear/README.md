# VoxGolem Wear capture

This is an independent Wear OS application Gradle root. It uses the phone's
application ID (`dev.gitblame.voxgolem.android`) so the default Android debug
keystore signs both packages consistently. Its source is not generated by
Tauri. Build from this directory with `./gradlew :app:assembleDebug` and run
`./gradlew :app:testDebugUnitTest`.

## Watch-to-phone contract

The phone advertises the Wear Data Layer capability
`voxgolem_capture_phone_v1`. The watch refuses ambiguous multiple reachable
receivers instead of selecting an arbitrary node. Wire traffic uses
`/voxgolem/capture/v1`:

* `start`, `ready`, `partial`, `final`, `stop`, `receipt`, and `status` are
  bounded JSON messages on `MessageClient` paths. Text hypotheses replace the
  prior full hypothesis and are accepted only for the active capture/session
  and increasing revisions; final text is terminal for that session.
* `live/<captureId>/<sessionId>` is a channel. The opening is a 32-bit
  big-endian JSON-header length and UTF-8 header (`protocol`, identity, PCM
  format, and `startedAt`). Frames are 64-bit sequence, 32-bit byte length,
  then PCM16LE bytes, with `-1` sequence as end-of-stream. Frames are bounded
  to 100 ms. A full live queue drops only live preview; it never blocks or
  drops the local recording.
* `archive/<captureId>/<attemptId>` is a finite channel. It begins with a
  32-bit big-endian bounded JSON-header length/header with `protocol`,
  `captureId`, `attemptId`, `sampleRate`, `channels`, `bitsPerSample`,
  `frameCount`, `wavBytes`, `sha256`, `finishDate`, and `timezone`, then a
  64-bit big-endian stream byte length and exactly that many WAV bytes. The WAV
  includes its 44-byte RIFF header; `sha256` covers the entire WAV. Channel
  completion alone is not a receipt. Only a matching `receipt` message with
  the archive SHA-256 changes the phone transfer badge. The watch never deletes
  local recordings automatically.
* `pending/<captureId>` is a small urgent DataItem with immutable completion
  metadata, not audio. It advertises an outbox item after local finalization.

The current app supports explicit Stop, a 10-minute maximum, and an advance
notification. Ambient events are diagnostic-only. Arm-down stopping is off until
the user measures distinct raised/lowered postures through the calibration UI.
The personalized motion policy still requires physical verification; no gesture
accuracy is claimed. No wake-word or
silence stopping is used.

The service uses the shared SQLite `CaptureRepository`, shared `CaptureRecord`
contract, shared `CaptureProtocol`/`TranscriptReducer`, and shared
`PcmRecordingWriter` through watch-specific adapters. The independent Wear root
uses Gradle's `prepareCaptureDomainSources` task to package only the shared
domain/storage files from their maintained owner. The phone plugin also has a
phone-only `:tauri-android` dependency. The watch APK
never compiles the phone Tauri plugin or listener source files. All local audio
remains durable if the phone is absent. Outbox retries query remote status
before resending an in-flight transfer, use bounded backoff, and keep the
original WAV until an explicit future cleanup flow is implemented.
